# Better Auth API Reference (`/api/auth/*`)

This document captures the full Better Auth HTTP surface exposed by this backend.

These routes are generated by Better Auth (via `@thallesp/nestjs-better-auth`) and are not directly defined as Nest controllers in app source files. Use this file as the primary endpoint reference for frontend integrations, debugging, and feature development.

## Source and scope

- OpenAPI source file: `/Users/artazasameen/Downloads/api-1 (1).json`
- OpenAPI version: `3.1.1`
- API title/version: `Better Auth` `1.1.0`
- Server URL in spec: `http://localhost:3000/api/auth`
- Operation count: `42` operations across `39` paths
- Typed request/response contracts: `apps/backend/docs/auth-api.types.ts`

## Request/response types

Detailed TypeScript contracts for requests and responses are defined in:

- `apps/backend/docs/auth-api.types.ts`

This includes:

- shared models (`User`, `Session`, `Account`, `Verification`)
- one request/response type pair per operation
- explicit `params` / `query` / `body` shapes
- `unknown` markers where OpenAPI export omits request or success schemas

## Base URL and auth behavior

- Base path: `/api/auth`
- Security schemes declared:
  - `apiKeyCookie` (cookie-based apiKey, cookie name: `apiKeyCookie`)
  - `bearerAuth` (HTTP bearer token)
- Effective operation-level security in this export: every operation declares `bearerAuth`.
- In browser-based frontend usage, Better Auth session cookies are still commonly used. Treat this export as canonical for route shape and request/response contracts, and validate runtime auth behavior in your environment when implementing flows.

## Shared response/model schemas

Core shared schemas from the spec:

- `User`
- `Session`
- `Account`
- `Verification`

Common non-2xx error payload shape:

- `{"message": "..."}` for most `400`, `401`, `403`, `404`, `429`, `500` responses.

## Important spec caveats for implementers

- `/callback/{id}` is defined without explicit path parameter metadata and without any `2xx` response schema in this export.
- `/sign-in/email-otp` has success schema but no request body schema in this export.
- Some operations define required properties inside JSON schema but do not mark `requestBody.required: true`; follow endpoint semantics and SDK behavior when in doubt.

## Frontend integration notes (agent-focused)

- Keep auth API access isolated in `apps/frontend/src/api/*.api.ts` + `apps/frontend/src/hooks/api/use-*.ts`.
- Use `axiosInstance.request({ url, method, data, params })` for all calls.
- For browser session flows, ensure credentials/cookies are sent consistently and callback URLs match configured frontend origin.
- Use this document as path/contract reference, and validate behavior against runtime when auth mode (cookie vs bearer) differs between environments.
